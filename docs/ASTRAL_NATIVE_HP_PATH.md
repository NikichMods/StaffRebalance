# Astral: нативный путь от попадания до HP

Область проверки — обычная положительная ветвь попадания базового Astral-снаряда в боевого персонажа. Основание для выбора источника — [статическая карта](STATIC_COMBAT_RESEARCH_01.md) и [боевой прогон 05](COMBAT_OBSERVATION_01.md#результат-боевого-прогона-05) на ревизии отчёта `35102355067723f2680d00128c19a58fae1ec03d`. В прогоне наблюдалось создание источников. Порядок ниже установлен статически, без нового игрового запуска.

## Идентичность и проверка

- Steam 1.09, build 12996889, UE 4.27, Win64. SHA-256 `Genesis-Win64-Shipping.exe`: `ddea6b5ca5d34836f01702993d20209c2595367287e6cd5a135a7ace1958b1c0`. Ниже адреса — RVA относительно image base `0x140000000`, применимые к этим байтам.
- Связка UHT и CUE4Parse из первого этапа устанавливает класс и наследование источника. Для нативной части использованы локальный PE и декодирование отдельных x64-диапазонов. Границы функций сверены по `.pdata`, включая chained unwind. Имена отражённых функций сверены по регистрационным парам имя/exec thunk и по телам событий. Остальные функции обозначены RVA и наблюдаемой ролью.
- Контрольная проверка записи HP — независимые отражённые маршруты чтения и изменения. `GameGlobal.GetHP`: thunk `0x12715C0` → `0x110BA90` → `0x114B5C0`, чтение `[Character+0x4E0]+0xD8`. `GameGlobal.AddHP`: `0x1261AA0` → `0x1106D40` → `0x11485E0` → `0x10C1C60`. `GameGlobal.SetHP`: `0x1289250` → `0x1112870` → `0x11507B0` → `0x10C6B30` → `0x10C1C60`.

## Цепочка

| Шаг | Нативное доказательство |
| --- | --- |
| Развилка контакта | В диспетчере `0x10B3F50` вызов по адресу `0x10B4402` передаёт управление обработчику персонажа `0x10B37A0`. Отдельный переход через вызов `0x10B43DE` ведёт в сценический обработчик `0x10B51F0`. Третья ветвь через `0x10B43F0` вне объёма проверки. |
| Проверка цели и данные контакта | В обработчике персонажа участок `0x10B3CC5` получает UClass `/Script/Genesis.GenesisCharacter` через `0x1296320` и проверяет наследование у `0x10B3D07`. После проверки цели и подготовки результата через `0x10AF7E0` вызов `0x10B3DC2` передаёт в `0x114D890` четыре аргумента: цель, исходный projectile, компонент попадания, указатель на подготовленный результат. |
| Владелец расчёта | `0x114D890` берёт компонент цели по `+0x4E0` и передаёт управление в `0x10C53E0`. Тот временно сохраняет projectile и hit component по `+0x218` и `+0x220`, копирует данные попадания, вызывает `0x10C44F0` у `0x10C5467` и очищает обе ссылки после возврата. |
| Расчёт | В `0x10C44F0` обычная ветвь вызывает `0x10CEE30` у `0x10C45C1` с целью и projectile. Сумматор перебирает восемь индексов, читает кэшированные величины через `0x10B0130`, масштабирует их величиной projectile по `+0x2C4` и учитывает поправки цели через `0x10CEC30`. У `0x10C45D1` результат дополнительно масштабируется величиной компонента цели по `+0x380`. Дальнейшие развилки учитывают защиту. Полная формула и семантика всех полей не восстанавливались. |
| Уведомление перед применением | У `0x10C4656` положительная ветвь вызывает обёртку `GenesisCharacter.ProjectileHitEvent` (`0x1296DC0`). Контекст — цель, параметры — тот же projectile, hit component, позиция и копия рассчитанного `float Damage`. Обёртка разрешает имя события и передаёт блок параметров в виртуальный вызов `+0x220`. |
| Запись HP | У `0x10C4932` меняется знак положительной величины, вызов `0x10C493C` передаёт отрицательную дельту в `0x10C1C60`. Функция использует текущие HP и верхнюю границу по `+0xD4`, записывает ограниченное значение по `+0xD8` у `0x10C1DEF`, а на условной ветви применяет нижнюю границу у `0x10C1E02`. После записи вызывается `0x114ECD0`. Между уведомлением и вызовом записи есть дополнительная развилка, способная обнулить дельту. |
| События после обработки и для сцены | `BaseProjectile.ProjectileOverlapCharacter` (`0x1245590`) вызывается у `0x10B3E2E` после возврата нативной обработки персонажа. Сценическая ветвь вызывает отдельные обёртки `ProjectileOverlapScene` и `ProjectileOverlapGameEventObject` у `0x10B53C2` и `0x10B5593`. Это различение на входе в расчёт персонажа, без обобщения на все разрушаемые объекты. |

`GameGlobal.DamageCharacter_Cpp` (thunk `0x1266BE0` → `0x1108730`) самостоятельно обрабатывает массив целей и использует `0x11485E0` для изменения HP на абсолютную величину и долю от максимума. В исследованном пути projectile вызов идёт напрямую в компонент. `BaseProjectile.GetBaseDamageRate` (thunk `0x1245AC0` → `0x10B0120`) читает поле `+0x6DC`. Сумматор использует отдельный прямой getter `0x10B0130`, что согласуется с отсутствием `RATE_CALL` в прогоне 05. Нативный callback, выявленный на положительной ветви, адресован событию цели `ProjectileHitEvent`. Прогон 05 наблюдал другое событие, `BaseProjectile.CharacterHitted`.

## Доступ из UE4SS и привязка к атаке

- **Наблюдение до штатной записи HP — статический кандидат.** Сигнатура `ProjectileHitEvent(ABaseProjectile*, UPrimitiveComponent*, FVector_NetQuantize, float)` даёт цель и исходный projectile в одном вызове. Прогон 05 исключал этот hook из-за struct по значению. Для UE4SS `v3.0.1-1181-g83330635` остаётся проверить конкретную загруженную реализацию на классе цели и безопасную обработку сигнатуры. Скриптовый callback может идти после тела Blueprint, но всё ещё внутри обёртки, до возврата во внешний нативный расчёт. Доступность и порядок описаны в [R-008](https://github.com/NikichMods/Asterigos-Research/blob/09d60c739143c8f61aea60731b83fffee06d3861/docs/VERIFIED_RUNTIME.md#r-008--ue4ss-callback-boundaries-for-observation-2026-10-28). Значение события может отличаться от фактической дельты HP.
- **Изменение до записи HP — безопасная точка в текущем Lua API не установлена.** Обёртка получает копию `Damage`. Нативный вызывающий код сохраняет собственную величину и использует её после события. Писатель `0x10C1C60` в этом маршруте вызывается напрямую. Отражённые `AddHP`, `SetHP` и `DamageCharacter_Cpp` не перехватывают этот прямой вызов.
- **Идентичность.** Нативный путь передаёт исходный projectile напрямую до уведомления и расчёта для конкретной цели. Для родительского выполнения skill стабильный token не найден. `GetDoingSkill` из прогона 05 отражает состояние владельца при наблюдении создания, а исследованная цепочка попадания не показывает, откуда восстановить идентификатор исходного выполнения. Связь со skill нужна отдельно от связи с экземпляром projectile.

Production gate остаётся **BLOCKED**. Для передачи следующего исследовательского шага достаточно одной точки `ProjectileHitEvent`: выяснить, доступна ли она для конкретного Blueprint цели с этой сигнатурой и можно ли получить наблюдение штатной ветви до записи HP. Отдельно остаются token выполнения, мутабельная точка до записи и границы вне обычной ветви.
