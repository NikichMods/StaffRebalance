# Astral Combo Boundary 01

**PASS для границы обычных Astral atk2/atk3 в наблюдённом сценарии.** Механика резерва остаётся за пределами прогона.

Из [статики](STATIC_COMBAT_RESEARCH_01.md) известны 2 и 3 болта в штатных timeline второго и третьего шага. [CombatObserver](COMBAT_OBSERVATION_01.md) уже записывал их с одинаковыми снимками skill внутри каждого шага. Снимок не разделяет два исполнения одного имени. [MagicalScabbards](https://github.com/NikichMods/MagicalScabbards/blob/6df404c2666fb2a23760efdc43f0ddde1ea2fd0a/docs/SCABBARD_DRAW_STOW_RESEARCH_02.md) доказал доставку native pre/post на локальном anim, включая первый Astral в более раннем прогоне. Для вопроса о порядке второго и третьего шага достаточно совместить эти два точных способа наблюдения. Широкий CombatObserver не нужен.

Проба сохраняет только строковые идентичности локальной Хильды и её `hilda_AnimBP_C`, проверяет владельца точного Astral-болта и пишет монотонный порядок native pre/post и script post. F4 запускает захват или ставит границу эпизода. Метка разделяет действия пользователя при разборе и не участвует в определении исполнения. F7 прекращает логирование и передаёт UE4SS раздельные native ID и парные script ID. В UE4SS `83330635` физическое снятие native-хуков отложено до следующего вызова. После F7 нужен один контрольный взмах в воздух, чтобы проверить строки снятия обоих native pre/post и отсутствие новых наблюдений.

## Прогон

1. В безопасном месте сделать прогревочный Astral-выстрел и дождаться конца анимации. F4, полное комбо 1 → 2 → 3.
2. Дождаться конца анимации. F4, повторить полное комбо.
3. Дождаться конца анимации. F4, выполнить 1 → 2 и не продолжать до третьего. Когда анимация закончится, начать новое полное комбо без дополнительной метки.
4. F7, один обычный контрольный Astral-выстрел в воздух, дождаться конца анимации и выйти. Срез резерва и CombatObserver выключены.

PASS требует отдельной упорядоченной пары Begin/End для каждого наблюдаемого исполнения atk2 и atk3, 2/3 собственных болтов между переходами, различимости повтора и прекращения после второго шага по событиям и подтверждённого снятия хуков. Если Start/End вложены, пропущены или расходятся с болтами, отчёт фиксирует точное ограничение. Сценарий проверяет прекращение продолжения игроком. Прерывание от получения урона или других событий в него не входит.

- Каждый atk2/atk3 получил один Begin. В pre нужный skill был в `pending`, в post перешёл в `doing`. Все 21 болт прогона имели разные идентичности и одного владельца. Для каждого болта atk2/atk3 оба getter совпадали с открытым исполнением.
- После последнего болта один End с тем же `doing` закрывал исполнение, post показывал `None`. При естественном завершении серии дополнительно приходил End с `doing=None` и в pre, и в post (seq 24–25, 45–46, 59–60, 79–80). Он не закрывает новое исполнение. После остановки на atk2 не было Begin/болтов atk3, затем пришёл свежий Begin первого шага (seq 61–62). Для различения достаточно событий, без таймеров и ручных меток.
- Наблюдаемая граница достаточна для узкого кандидата: открывать исполнение в Begin post при нужном переходе, списывать только на первом подтверждённом болте, сохранять режим для остальных, закрывать на соответствующем End. Здесь не проверялись собственно запись режима, начисления, внешние прерывания, другие навыки или совместная установка этих хуков с dev-резервом.
- F7 сняла script ID 14 и передала native пары 10/11 и 12/13. Контрольный выстрел завершил снятие всех четырёх native callbacks (строки 788–793), новых наблюдений после STOP нет. После выхода отключён только маркер пробы, остальные маркеры и `mods.txt` совпали.
