## Первый проверяемый вопрос: штатный коэффициент Astral

**Обычный Astral A/B — PASS. e804 — NOT TESTED.** [Отчёт](ASTRAL_NATIVE_HP_PATH.md#штатный-коэффициент-обычного-astral--2026-11-07) связывает штатный spawn rate, запись и восстановление e804 и нативный consumer. Проверка e804 независима от melee-исследования.

1. [Research-only A/B probe](ASTRAL_RATE_PROBE_01.md) подтвердил запись до попадания и снижение штатного Damage на первом одиночном Astral-выстреле. Остаётся проверить сохранение масштаба через штатное восстановление e804. Провал этой проверки возвращает вопрос о точке изменения.
2. [Reserve Slice 01](RESERVE_SLICE_01.md#игровой-pass-автоматического-среза--2026-11-07) подтвердил первоначальный цикл для первого Astral. Затем [Dev Prototype 01](DEV_PROTOTYPE_01.md#игровой-интеграционный-pass-astral-atk2atk3--2026-11-07) подтвердил все три обычных Astral-шага с единым режимом 2/3 болтов и единственным списанием за шаг. Специальные/переключаемые действия и e804 остаются за пределами PASS.

**Критерий достаточности статического этапа выполнен:** найдены владелец, writer, consumer и проверяемая точка изменения. Production READY требует игрового результата и приёмки. Узкая проверка коэффициента сама по себе не закрывает реализацию резерва.

## Следующие независимые границы (после первого ответа)

- **Melee credit — полный обычный Astral source whitelist в dev, интеграционный PASS для трёх добавленных источников.** [Статика combo](STATIC_COMBAT_RESEARCH_01.md#охват-обычных-melee-комбо--2026-11-08) связала 20 обычных шагов пяти видов оружия с восемью точными class/row-парами. Первая атака всех пяти оружий проверена в игре; [игровой проход трёх новых пар](DEV_PROTOTYPE_01.md#игровой-результат-диагностики-melee-комбо--2026-11-08) подтвердил 4-й удар кинжалов и 3-й/4-й удары браслетов. [Отдельный непрерывный повтор браслетов 2026-11-09](DEV_PROTOTYPE_01.md#повтор-одной-серии-браслетов-и-очистка--2026-11-09) дал **4 кредита за 4 шага** (1/1/1/1) и **4 подавленных повторных callback**, `diag_total=4/50` при действующем резерве 3; F7 и контрольный Astral-выстрел подтвердили удаление девяти script hooks и двух native pre/post пар. Более ранняя полная серия кинжалов дала **5 кредитов** (2/1/1/1); 7 кредитов браслетов в первом общем сеансе относились к нескольким сериям, не одной. Принятое правило dev остаётся **+1 за уникальную source–target пару**: оно не доказывает, что повторные тики одной сферы физически ложны. **Завершено** для указанных live gates; дополнительные повторы первых ударов/полных Astral-комбо не нужны без нового дефекта или меняющегося условия. Не объявлять игровой PASS отдельно для всех 20 шагов, потому что их все подряд не наблюдали. **Melee elemental candidate реализован для всех четырёх стихий; Fire 8/8 live PASS:** точные 8 class/row семейств из cooked-карты × `_astral/_fire/_ice/_thunder` = 32 допускаемые пары; [код `885a642`](https://github.com/NikichMods/StaffRebalance/commit/885a6428d4108e7e1f18d1785d21ff9528a32281), [явное логирование элемента `a882176`](https://github.com/NikichMods/StaffRebalance/commit/a882176e2b8a4768c4ed2ab6a4aaa48ce5883579), [Lua mock CI PASS 42532107063](https://github.com/NikichMods/StaffRebalance/actions/runs/42532107063). Обычный unmapped `hilda_cudgel_C` специально не допускается: remap-стихии молота используют `hilda_cudgel_fire_C`. Реальные Fire hits **PASS** ([игровой журнал 2026-11-09](DEV_PROTOTYPE_01.md#игровой-результат-fire-melee--2026-11-09)), Ice/Thunder hits **NOT TESTED**. Выполненный Fire gate: один live-сеанс, два полных melee-комбо (кинжалы, браслеты) плюс по одному обычному попаданию копьём, молотом и мечом со щитом; по `MELEE weapon=... element=fire` подтвердить все восемь семейств и диагностический tally, без принудительного опустошения реального резерва 3. ## Стоп-условия и разделение статусов

- **Game design** принят; **Astral и Fire 1–3 + первые обычные атаки всех пяти melee-типов имеют dev integration PASS**, но полные melee-комбо/elemental rows, Ice/Thunder, e804, специальные умения, HUD и жизненный цикл ещё не проверены. **Production gate BLOCKED** до соответствующих per-change gates, тестов и приёмки.
- Не возвращаться к отложенному нативному CALL 0x10C493C, CDB hardware breakpoints или broad damage rewrites только из-за отсутствия более простого решения.
- Если минимум зависит от выбора новых игровых компромиссов, сформулировать последствия для пользователя до изменений. Не выдавать исторический NO VERIFIED IMPLEMENTATION PATH строгого HP-контракта за вердикт для нового дизайна.
- История предыдущих планов сохранена в Git, в [feasibility review](DAMAGE_RESERVE_SEAM_FEASIBILITY_01.md) и [исходном runtime ТЗ](RUNTIME_OBSERVATION_TASK_01.md); старые планы точного HP-учёта и токенов атак не действуют.

### Thunder staff basic: ограниченный dev-кандидат — 2026-11-09

[Source `63c6890`](https://github.com/NikichMods/StaffRebalance/commit/63c6890ac59fdde2382ba4c71fe410ada5a61774) добавляет **только** базовые прямые Thunder bolts (`hilda_staff_bolt_thunder_C` + exact `hilda_staff_bolt_thunder`) и четыре обычных skill rows `atk1_idle/atk1/atk2/atk3_thunder`. Native `BeginDoSkill` — обязательный токен границы исполнения, первый настоящий болт списывает ровно один заряд в strong, оставшиеся 1/2/3 болта наследуют режим; при резерве 0 — изменение штатного `DamageRate` ×0.5 для каждого источника. Повторный callback, foreign owner/row, специальный skill, несовпадение execution, e804 с ненулевым `Original Damage Rate` — fail-closed. Класс может не быть загружен: тогда Thunder hook пропускается без блокирования проверенных Astral/Fire. Mob-hit лог Thunder отделён от melee-кредитов и не пополняет резерв.

**[CI 42533630109](https://github.com/NikichMods/StaffRebalance/actions/runs/42533630109) PASS** (Lua 5.4 syntax/mock), runtime Thunder NOT TESTED. Не объявлять source/owner/skill callback и итоговый HP-урон проверенными. Следующий независимый рабочий блок — **Ice staff**, где нужно связать основной болт с дочерними `hilda_staff_bolt_ice_hit` damage pulses на общем `sphere_150_C` при исключении `hilda_staff_bolt_ice_vfx`. Один выстрел/шаг — одно списание; периодические импульсы наследуют режим, не создают новых списаний. Основание — [STAFF_ELEMENTAL_COVERAGE_01](STAFF_ELEMENTAL_COVERAGE_01.md#ice-идентификатор-дочернего-импульса). Достаточное доказательство для dev — exact class/row/parent owner и mock; не нужен отдельный read-only observer до первой экспериментальной интеграции, если идентичность source rows подтверждена. Game integration Ice/Thunder только при доступных стихиях и проверенном установленном SHA. Production BLOCKED.

**Ice child design checkpoint (2026-11-09):** [минимальная модель](STAFF_ELEMENTAL_COVERAGE_01.md#ice-минимальная-модель-наследования-от-родителя--2026-11-09) подтверждает по cooked+native, что повреждающий `sphere_150_C` отличается от VFX точным `ProjectileDataName` и получает Actor Owner = исходный Ice bolt. Рекомендован Fire-подобный parent-ID mode capture на Bolt BeginPlay + отдельный exact-row guard на каждом child BeginPlay; **не удалять parent mode после первого pulse**, поскольку штатная timeline создаёт повторные hit-импульсы. Один debit за skill, наследование режима после End/нового skill; исключить VFX/Fourth/foreign parent, fail-closed при отсутствующей UFunction/owner. Это **design READY для узкого dev/mock**, но `sphere_150_C:ReceiveBeginPlay` и его live delivery ещё не подтверждены; без game PASS Ice не принят. Не вводить broad spawn, polling или native CALL.


**Ice staff basic реализован в dev (2026-11-09):** [`9874c1b`](https://github.com/NikichMods/StaffRebalance/commit/9874c1bfc9039c846334b349f2d0efbedeeb9bd0) + [`3f5d528`](https://github.com/NikichMods/StaffRebalance/commit/3f5d528debfa63f5703a9d00e702577e7daa1e6e), [Lua 5.4 CI PASS 42535221289](https://github.com/NikichMods/StaffRebalance/actions/runs/42535221289). Zero carrier-rate допускается. Parent mode не удаляется после первого child (повторные pulse-источники). VFX/Fourth и чужие источники исключены, опциональная связка Ice hooks не блокирует Astral/Fire/Thunder при недоступном классе. Уровень доказательств: static design + mock PASS; **Ice runtime NOT TESTED**. Следующий шаг без дополнительных больших исследований — только узкий игровой gate после разблокировки Ice: правильный row, живой parent, несколько pulses на одном bolt, distinct weak/strong notified damage, hook cleanup. ### HUD: начало работы 2026-11-09

При следующем visual prototype дополнить ресурс обозначением силы посоха, event-driven gain/spend response и умеренным first-use context cue; проверить также нулевой/weak режим и сохранение native CombatHUD 0.4.1. ### Визуальный режим staff projectile — новое смежное направление 2026-11-09
