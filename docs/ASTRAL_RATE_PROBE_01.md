# Astral Rate Probe 01 — исследовательский A/B-тест

**Статус:** локальная техническая проверка пройдена, игровой A/B-прогон ожидается. Production gate — BLOCKED. Исходник: [main.lua](../research/astral-rate-probe-01/StaffRebalanceAstralRateProbe/Scripts/main.lua).

## Цель и доказательство

Проверить пост-обработчик ReceiveBeginPlay конкретного hilda_staff_bolt_astral_C. На F6 уменьшать отражённый DamageRate снаряда вдвое, а если Blueprint сохранил положительное Original Damage Rate, уменьшать и его. Штатный e804 при достижении порога около 800 units должен восстановить уже уменьшенное значение. Независимая проверка — настоящий ProjectileHitEvent.Damage, не наше собственное вычисление и не потеря HP. Технические основания: [ASTRAL_NATIVE_HP_PATH.md](ASTRAL_NATIVE_HP_PATH.md#штатный-коэффициент-обычного-astral--2026-11-07).

Исследование read-only доказательств уже установило порядок нативного spawn → Blueprint BeginPlay → tick/контакт, поле DamageRate +0x2C4 и отличие SetBaseDamageRate. Здесь тестируется доступность отражённого write и его результат, а не вся игра.

## Ограничения

- Research-only Lua: никакой отдельной энергии, баланса, HUD, игровых сохранений, DLL, native detour или patch EXE.
- До первого F4/F6 хуки не установлены и ничего не меняется. F4 — vanilla-контроль, F6 — слабый коэффициент 0.5, F7 — stop/снятие хуков до конца сессии.
- Записи допускаются только в конкретный экземпляр по class, ProjectileDataName, GetCharacterOwner == текущая Хильда, GameThread и отражённым типам полей. На конфликте контрактов stop/fail-closed. Для e804 парная запись с проверкой и попыткой немедленного rollback при ошибке.
- Изменения конкретного живого снаряда session-persistent до его уничтожения. Не сохранять игру с активным тестом; после теста выйти из игры без сохранения. При ROLLBACK_FAILED немедленно выйти без сохранения.
- Выключение через enabled.txt только на закрытой игре; потенциальное включение через mods.txt проверить отдельно.

## Установка (Codex)

1. Сверить рабочую ветку и текущий commit; актуальные DevRules, AGENTS.md, REQUIREMENTS.md и эту инструкцию. Проверить установленные версии Steam 1.09 / UE4SS 83330635, свои и сторонние моды, возможный конфликт горячих клавиш.
2. Убедиться, что StaffRebalanceCombatObserver выключен: он использует F4/F7 и может одновременно регистрировать тот же BeginPlay. Ничего другого не удалять.
3. Скопировать каталог research/astral-rate-probe-01/StaffRebalanceAstralRateProbe в UE4SS/Mods/StaffRebalanceAstralRateProbe. Включить enabled.txt только для теста; сохранить прежние маркеры и старые файлы при наличии.
4. Игровой сценарий: загрузить Хильду около обычного моба; не сохраняться. F4 → один обычный Astral-выстрел по сопоставимой цели; дождаться исчезновения снаряда; F6 → такой же выстрел. Если класс ещё не загружен и контракт не найден, сделать прогревочный выстрел и повторить F4.
5. При наличии e804 дополнительно сравнить краткую и большую дистанцию отдельно в vanilla и weak; если талант недоступен, явно зафиксировать NOT TESTED. Не подменять разные типы врагов или защищённые состояния друг другом.
6. F7 после исчезновения снаряда, выйти без сохранения; Codex закрывает UE4SS.log, выключает только этот enabled.txt, проверяет собственные файлы и SHA-256 закрытого лога, фиксирует наблюдения в документах.

## Приёмка одного прогона

| Событие | Требуемое свидетельство |
| --- | --- |
| ARMED / KEY / ENGINE_TICK_ENTRY / HOOKS_READY / MODE | Сценарий реально активирован и два точных hook зарегистрированы |
| BOLT mode=vanilla | Штатное значение до/после идентично |
| BOLT mode=weak | DamageRate после вдвое меньше значения до; при e804 также масштабирован Original Damage Rate |
| HIT spawn_mode=vanilla и weak | Отдельное игровое уведомление с Damage и rate; на сопоставимой цели weak Damage заметно меньше |
| e804 до/после восстановления | Масштаб сохраняется через штатный сброс Original Damage Rate, если талант доступен |
| STOP hooks_remaining=0 | Собственные хуки сняты, можно выключить мод после закрытия игры |

**Не выдавать PASS** за один успешный SetPropertyValue, за численное сопоставление разных врагов или за вывод о реальной потере HP. Урон по частям тела, оборона и сопротивления могут менять соотношение уведомлений; для сравнения нужны одинаковые условия. При UNAVAILABLE, SKIP, DISABLED или ROLLBACK_FAILED выяснить причину вместо повторения боя.

## Локальная техническая проверка 2026-11-07

- На установленном Steam build 12996889 хеш EXE совпал с исследованным. Последний закрытый лог подтвердил UE4SS `83330635`. Оба Lua-хука опираются на наблюдения CombatObserver. Форма mob-уведомления уже подтверждена на Fire.
- В исходниках UE4SS `8333063595fa3c49ad307f3b0f732accbb760d25` проверены поиск свойства по FName, `GetPropertyValue`/`SetPropertyValue` и запись Lua number через обработчик `FloatProperty`. У `XProperty` нет `IsValid()`. Для отсутствующего дескриптора `GetFullName()` возвращает nil. Скрипт сверяет тип и имя через этот метод, а `DamageRate` дополнительно по offset `0x2C4`.
- Lua 5.4 с имитацией UE4SS подтвердил синтаксис, отсутствие записи в vanilla, ослабление обычного болта и пары e804, корреляцию с аргументом события, пропуск дубля и чужого источника, отказ при неверной форме события или свойства, конфликт клавиш, очистку после частичной регистрации и F7. Отдельно проверены тихий отказ записи и ошибка после изменения второго поля. Восстановление первого поля выполняется даже при отказе восстановить второе.
- В текущем списке активных модов конфликтов F4/F6/F7 не обнаружено. F6 занимал OutfitCheatMod в старом логе, но на момент проверки этот мод отключён. На старте проба проверяет доступность клавиш.
- Реальное выполнение записи в живой снаряд, наблюдение `ProjectileHitEvent.Damage` на Astral и сохранение масштаба после штатного восстановления e804 проверяются в игре.
