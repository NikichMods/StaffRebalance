# Dev Prototype 01 — переход от проверенного среза к разработке

**Ветка:** `dev/reserve-core-01`. **Production gate: BLOCKED.** Исходная исследовательская версия [Reserve Slice 01](RESERVE_SLICE_01.md#игровой-pass-автоматического-среза--2026-11-07) прошла Lua 5.4 mock и узкий игровой прогон. Это не приёмка полного StaffRebalance.

## Цель этапа

Развивать **уже работающую** механику ограниченного staff damage reserve вместо нового исследовательского каркаса. Первый dev-коммит добавляет только отдельную рабочую копию ранее проверенного Lua-исходника: [dev/StaffRebalanceDev/Scripts/main.lua](../dev/StaffRebalanceDev/Scripts/main.lua). Её содержимое **побайтно идентично** `research/reserve-slice-01/StaffRebalanceReserveSlice/Scripts/main.lua` на исходном SHA `c1c28dfd28f5acee901a5aa4ce1037fa82871e19`. Следовательно, новая функциональность этим переносом не заявлена. Сохранён исходный исследовательский файл с его историческими evidence и хешами.

## Подтверждённая рабочая граница

- Только первые обычные Astral-действия `hilda_staff_atk1` / `hilda_staff_atk1_idle`, проверенный `ReceiveBeginPlay`, одна оплаченная атака на один штатный bolt для этих двух timeline.
- Экспериментальные числа: ёмкость 3, стоимость сильного выстрела 1, слабый `DamageRate × 0.5`, melee-кредит +1 за подтверждённый контакт первого удара кинжалами с `m052_arvicolina_BP_C`.
- Conduit: закрытие меню без отдыха не пополняет; подтверждённый отдых по связанной цепочке возвращает полный запас.
- Контроль research-only: F4 включает сессию, F7 отключает и снимает свои хуки; ресурс живёт только в Lua-памяти. Изменения игровых save отсутствуют в коде, но во время испытания сохранения избегать.

### Первый практический шаг

**Не превращать список в одновременную реализацию.** Установить исходную dev-копию локально только после сверки её побайтной идентичности с прошедшим исследовательским кодом и локального запуска уже существующего:

```text
lua research/reserve-slice-01/tests.lua dev/StaffRebalanceDev/Scripts/main.lua
```

Затем Codex проверяет расположение `UE4SS/Mods/StaffRebalanceDev/Scripts/main.lua`, отсутствие ранее активных StaffRebalance observers/probes, `enabled.txt` и `mods.txt`. **Не включать одновременно оба варианта одного и того же наблюдателя.** Перед первым live-прогоном зафиксировать состояние установленного baseline. Контракт F4/F7 остаётся временным: его удаление требует отдельной проверки запуска и завершения жизненного цикла.

После переноса следующий изменяющий поведение шаг — **один вариант расширения охвата базового Astral-комбо**, начиная с проверки существующих событий skill/Timeline, не с машинного кода и не с нового общего attack-token framework. Если действие нельзя безопасно отличить от нескольких projectile, зафиксировать узкий BLOCKED вместо выдуманной оплаты. Отдельные melee-цели, Fire и HUD не смешивать с этим непроверенным изменением в одном candidate.

### Проверка штатной границы Astral-комбо — 2026-11-07

**Новый подтверждённый технический кандидат, не игровой PASS для atk2/atk3.** Общий [Asterigos-Research: skill-hook delivery](https://github.com/NikichMods/Asterigos-Research/blob/main/docs/VERIFIED_RUNTIME.md#cudgel-socket-transition-and-skill-hook-delivery--observed-2026-11-06) зафиксировал на том же Steam/UE4SS baseline доставку native pre/post `/Script/Genesis.BaseCharacterAnimInstance:BeginDoSkill` и `:EndDoSkill` для локального `hilda_AnimBP_C`. На одном `hilda_staff_atk1_idle` native Begin перевёл skill из `GetToDoSkill` в `GetDoingSkill`, а End очистил doing. [Исходный runtime-отчёт](https://github.com/NikichMods/MagicalScabbards/blob/6df404c2666fb2a23760efdc43f0ddde1ea2fd0a/docs/SCABBARD_DRAW_STOW_RESEARCH_02.md#результат-повтора-2026-11-06) и [существующий read-only hook](https://github.com/NikichMods/MagicalScabbards/blob/6df404c2666fb2a23760efdc43f0ddde1ea2fd0a/research/scabbard-draw-stow-02/observer-02/Scripts/main.lua) содержат точные пути, отсутствие аргументов, фильтр anim и правильную пару native hook IDs. Это **не** те `GenesisCharacter.BeginSkillStateEvent/EndSkillStateEvent`, которые уже зарегистрировались, но не доставили событий в [CombatObserver 05](COMBAT_OBSERVATION_01.md#результат-боевого-прогона-05).

**Предпочтительная минимальная конструкция для проверки:** использовать событие *начала выполнения skill* только как новый локальный идентификатор исполнения, а уже проверенное `ReceiveBeginPlay` первого подходящего Astral-болта — как подтверждение выполненного действия и момент единственного дебета. Прочие болты того же исполнения получают сохранённый strong/weak-режим, даже если запас после первого стал нулём. Отсутствие подтверждённого начала, чужая Хильда или неподдержанный skill — не разрешение платить за каждый bolt. Не вводить счётчики 2/3 как источник истины, общий attack-token framework, polling или native patch.

**Результат read-only проверки:** [PASS для обычных atk2/atk3](ASTRAL_COMBO_BOUNDARY_01.md#игровой-результат-2026-11-07). После одного Begin post получено 2/3 болта, затем один End с совпадающим doing. Дополнительный пустой End в конце серии не обозначает исполнение. В этой пробе снятие native и script hooks проверено. Совместная работа с dev-резервом и фактическое списание остаются отдельным gate.

### Dev-кандидат: одно списание за Astral atk2/atk3 — 2026-11-07

**Gate READY для узкого candidate, runtime NOT TESTED.** Основание: [live boundary PASS](ASTRAL_COMBO_BOUNDARY_01.md#игровой-результат-2026-11-07), штатные pre/post `BeginDoSkill/EndDoSkill`, проверенный `ReceiveBeginPlay` и Astral `DamageRate`. Изменены только два базовых skill `hilda_staff_atk2` / `hilda_staff_atk3`. По Begin post на локальном anim открывается исполнение; первый проверенный bolt назначает режим и при наличии энергии оплачивается один раз; остальные bolts исполняются с тем же strong/weak независимо от промежуточного остатка. End pre с совпадающим doing закрывает исполнение; дополнительный End(`None`) игнорируется. Смена выполнения сбрасывает старую границу без time/token-эвристик. Без Begin/подтверждённого anim — безопасный SKIP, без дебета.

**Сохранённые границы:** первый `atk1[_idle]`, проверенный кинжальный контакт и Conduit остаются прежними. `Original Damage Rate != 0` пропускает ещё не проверенный e804; если это первый bolt шага 2/3, весь этот шаг отмечается unsupported, чтобы следующий bolt не был ошибочно оплачен как первый. Никаких новых melee/Fire/HUD/save/load/death решений. Source identity и один-shot дедупликация остаются прежним узким срезом, не общим решением lifetime/recycling.

В журнале `PASS: dev Astral combo 2/3 action debit + inherited mode, reserve legacy guards`. Это подтверждает только модель и синтаксис, не реальный UE4SS. Следующий gate: запустить Lua 5.4 тесты для точного dev SHA, затем установить только один активный dev-мод при отключённых research-observers, провести короткий реальный цикл `atk1 → atk2(2 болта) → atk3(3 болта)` со strong из остатка 1, weak при 0 и повтором после melee. Native удаление в UE4SS может быть отложено до следующего выполнения; проверить физическое снятие native callbacks после F7, не считать одно `UnregisterHook` достаточным доказательством. Это не production PASS и не принятие чисел.

## Критерий завершения dev-этапа

Для расширяемой функции: owner, момент выполнения, результат и неизменяемые побочные эффекты подтверждены по ENGINEERING_RULES.md; mock проходит для собственных состояний; реальная игра подтверждает новый путь. При этом все остальные явно не поддержанные случаи безопасно остаются штатными и помечены как не охваченные, а не как успешно работающие. Только после расширения требуемого охвата и пользовательской приёмки можно готовить production release. Исследовательский raw-log не публиковать без необходимости; commit SHA + отчёт достаточно.
